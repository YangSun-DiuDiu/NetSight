## 一、现状与根因

- 租户隔离的"权威来源"是线程局部登录态：`SecurityUtils.getTenantId()` 读 Spring Security 的 `SecurityContextHolder`（未登录返回 0L）。
- `MybatisPlusConfig` 的 `TenantLineHandler`：`getTenantId()` = `SecurityUtils.getTenantId()`；`ignoreTable()` 在**未登录时返回 true（放弃全部租户过滤）**。
- 异步路径无登录上下文：
  - `@Async("eventExecutor")`（EventCenterService.asyncProcess）→ 线程池线程，无 SecurityContext；
  - `@EventListener`（WorkOrderEventListener）→ 同步监听，随 asyncProcess 线程执行（当前受益），但改为异步监听后即失效；
  - `@Scheduled` 定时任务（InspectionService.generateTasks 等）→ 无租户上下文。
- 后果：异步方法必须**手工补 eq(tenantId)**，漏一处即跨租户读写。现有加固点（保留中）：
  - WorkOrderService.autoCreateFromEvent (L219) / handleRecover (L264) / checkTenantOrder (L392-399)；
  - WorkOrderNotifier L48、NotificationChannelService L82/90/386/397、NotificationContactService L119、NotifyChannelService L190、EventCenterService L175-178、InspectionService L240-255、SparePartService L296、PushplusChannelSender L187、AuthService L166。

## 二、深化目标

让租户过滤对**所有执行路径同权**（同步请求 / @Async / @EventListener / @Scheduled），拦截器兜底生效，不再依赖"程序员记得加固"。

## 三、核心设计（三层保障）

**第 1 层 · 显式租户上下文（机制）**：新增 `common/context/TenantContextHolder.java`（ThreadLocal<Long>，set/get/clear）。

**第 2 层 · 拦截器升级（兜底）**：`MybatisPlusConfig.TenantLineHandler` 两级取值：

| 场景 | 现状 | 改造后 |
|---|---|---|
| 已登录请求 | SecurityUtils 取租户，正常过滤 | 不变 |
| 未登录但有 TenantContext | 跳过过滤（漏洞） | 按 TenantContext 过滤（仅忽略公共表） |
| 未登录且无 TenantContext | 跳过过滤 | 维持（登录/认证等场景必须） |
| 超管 | 跳过过滤 | 不变（超管语义不动） |

```java
public Expression getTenantId() {
    Long ctx = TenantContextHolder.get();
    if (ctx != null) return new LongValue(ctx);          // 显式上下文优先
    return new LongValue(SecurityUtils.getTenantId());   // 登录态兜底
}
public boolean ignoreTable(String tableName) {
    if (TenantContextHolder.get() != null) {
        return IGNORE_TABLES.contains(tableName);        // 有显式租户→必须过滤
    }
    // 其余逻辑保持现状（未登录跳过 / 超管跳过 / 公共表跳过）
}
```

**第 3 层 · 线程池传递 + 入口注入（纪律）**：
- `AsyncConfig.eventExecutor` 加 `TaskDecorator`：提交时捕获提交线程 TenantContext，执行前恢复、finally 清理（防线程池复用串租户）；
- `EventCenterService.asyncProcess` 入口：`TenantContextHolder.set(event.getTenantId())` + finally clear；@EventListener 同步监听自动继承；
- `@Scheduled` 定时任务（如 InspectionService.generateTasks）：方法内按 `plan.getTenantId()` 循环 set/clear，或按租户分组处理。

## 五、决策点（实施前需用户确认）

1. **存量手工 eq(tenantId) 是否删除** → 建议保留（纵深防御；超管分支下显式 eq 仍限定租户，删除会削弱语义）。仅约定：新代码由拦截器兜底、不再新增手工 eq。
2. **定时任务点检改造是否纳入本轮** → 不纳入则 InspectionService 维持现状并标记待办。
3. **超管语义**：拦截器对超管仍跳过过滤（维持现状），不影响"超管看全部"既有逻辑。
4. **登录/认证路径**（未登录、无显式上下文）仍跳过过滤 —— 登录接口查任意租户用户的必要条件，不动。

## 六、验证与回滚

- **验证**：构造无登录上下文的异步调用，断言查询 SQL 自动带 `tenant_id`；用两个租户的同设备数据做跨租户断言（工单自动归档、点检任务生成、联系人解析三处重点回归）。
- **回滚**：改动集中，回退 `MybatisPlusConfig` 与 `AsyncConfig` 两处即可恢复；TenantContextHolder 为空时行为与现在完全一致，对存量功能零影响。
