## 1. 交付内容

### 1.1 数据库
- `inspection_task` 新增列：
  - `approval_status varchar(20) NULL`
  - `approval_bill_id bigint NULL`
  - `attempt_no int NOT NULL DEFAULT 1`
- 新增索引：`idx_inspection_task_tenant_taskno`
- 迁移脚本：`docs/sql/inspection_task_confirm_approval.sql`
- tenant 17 流程定义：
  - 流程编码 `inspection_task_confirm_t17`
  - 流程名称 `点检任务确认`
  - 节点：开始 → `点检确认（租户管理员）`（`tenant_admin`）→ 结束

### 1.2 后端
- 点检提交后，在同一事务内按租户查找已发布流程并自动发起审批。
- 审批通过：任务 `approval_status=approved`、`status=2`。
- 审批驳回：任务 `approval_status=rejected`、`status=0`、`attempt_no+1`，保留历史审批单。
- 未配置流程：仅记录 warn，点检任务照常完成，不阻断业务。
- 审批事件只在最终态（通过/驳回）发布，避免中间节点提前归档。

### 1.3 前端
- 点检任务列表新增“审批状态”“轮次”列。
- 点检任务详情新增审批状态、执行轮次、审批单 ID。
- 提交成功提示追加“已发起‘点检任务确认’审批，等待租户管理员确认”。
- 统一待办审批弹窗新增“点检任务明细”（任务快照 + 点检记录）。
- “我的发起”增加业务类型“点检任务确认”。

## 9. 结论

点检任务确认审批的核心链路已打通并通过接口级端到端验证：

1. 运维人员提交点检任务后自动发起“点检任务确认”审批；
