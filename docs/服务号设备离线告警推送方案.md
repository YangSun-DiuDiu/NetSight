# 服务号设备离线告警推送方案（微信公众号模板消息）

> 版本：v1.0（方案稿，待确认后实施）　日期：2026-11-05
> 方向：**通过已认证的服务号向绑定用户推送设备离线告警**（模板消息），非接收用户消息。

---

## 1. 需求理解与目标

**一句话目标**：设备离线事件产生后，NetSight 系统调用微信公众号模板消息接口，把"设备离线告警"推送到已绑定微信的通知联系人手机上。

**链路全景**：

```
设备离线 ──► 事件中心 ──► 告警规则 ──► 模板组 ──► 公众号通道(wechat) ──► 微信模板消息 ──► 用户微信
              (EventCenter)  (NotificationRule)  (NotificationTemplate)  (WechatMpChannelSender)   (服务号)
```

前置依赖：用户先通过"绑定微信"把本人微信 openid 写入通知联系人（一次性操作）。

## 3. 总体架构（两条链路）

### 3.1 绑定链路（一次性，把 openid 写入联系人）

```
通知联系人页「绑定微信」按钮
   │  GET /wechat/oauth/authorize?contactId=5&state=随机串
   ▼
open.weixin.qq.com 网页授权页（snsapi_base 静默授权，无需用户确认信息）
   │  用户确认后微信 302 回调
   ▼
GET /wechat/oauth/callback?code=xxx&state=xxx
   │  后端用 code 换 openid（sns/oauth2/access_token）
   ▼
notify_contact.wechat_openid = openid   （按 state 里的 contactId 回填）
   │
   ▼
302 回前端 → 提示「绑定成功」（未关注用户同时提示先关注服务号）
```

> 说明：采用**网页授权**而非"关注事件回调"拿 openid——与你的方向一致（不做接收链路），且 snsapi_base 静默授权无需用户输入，体验最顺。模板消息仅能发给**已关注**用户，未关注者发送会报 43004，绑定页引导关注即可。

### 3.2 推送链路（告警 → 模板消息）

```
设备离线上报 ──► EventCenterService.asyncProcess
                   │  按规则模板组分发（现有逻辑，不改）
                   ▼
NotificationChannelService.dispatchByTemplateGroup
   │  组内模板：{sms模板, wechat模板}
   │  resolveReceiversByChannel(contacts, "wechat") → [openid1, openid2, ...]
   ▼
WechatMpChannelSender.send(receiverList=[openid...], contentVars=...)
   │  ① 取 access_token（缓存 7000s，失效自动重取）
   │  ② POST https://api.weixin.qq.com/cgi-bin/message/template/send
   ▼
微信服务号 → 用户手机收到模板卡片
```

## 4. 组件设计

### 4.1 WechatMpChannelSender（新增，核心）

**文件**：`netsight-server/src/main/java/com/netsight/modules/alert/channel/WechatMpChannelSender.java`

- 实现 `NotificationChannelSender`，`getChannelType() = "wechat"`，`getChannelName() = "微信公众号"`（与 `CHANNEL_WECHAT` 常量、yml `netsight.alert.channels.wechat` 对齐）
- **配置来源（两级）**：优先 `channelConfig`（notify_channel 实例 config_json，密钥走既有 AES 加密），缺省回退 `application.yml` 全局配置（WECHAT_APP_ID / WECHAT_APP_SECRET / WECHAT_TEMPLATE_ID）
- **access_token 管理**：静态缓存 7000s；请求返回 40001（invalid credential）时清缓存重取一次再发；mock 模式（WECHAT_MOCK=true）直接返回成功不调微信
- **发送**：`POST /cgi-bin/message/template/send`，body：
  ```json
  {
    "touser": "<openid>",
    "template_id": "<wx模板ID>",
    "url": "<可选，点击卡片跳转地址>",
    "data": {
      "first": {"value": "【设备离线告警】"},
      "keyword1": {"value": "SW-CORE-01"},
      "keyword2": {"value": "10.10.1.5"},
      "keyword3": {"value": "2026-11-05 14:30:00"},
      "keyword4": {"value": "高危"},
      "remark": {"value": "请及时处理"}
    }
  }
  ```
- **模板内容约定**：`notification_template.content` 存 JSON 字符串（渲染后），如：
  ```json
  {"first":"【设备离线告警】","keyword1":"${deviceName}","keyword2":"${deviceIp}","keyword3":"${alertTime}","keyword4":"${alertLevel}","remark":"请及时处理"}
  ```
  发送前用 `NotificationTemplateService.render` 渲染 `${var}`，再解析 JSON 组 data；解析失败降级为文本整段放入 remark。
- **频控/错误处理**：45026 频控限流记日志；43004 未关注跳过该 openid；多 openid 循环发送，单条失败不影响其余

### 4.2 openid 绑定模块（新增）

**文件**（`com.netsight.modules.alert.wechat` 新包）：
- `WechatOAuthController`：
  - `GET /wechat/oauth/authorize?contactId=` → 生成 state（contactId+随机串，Redis 校验）→ 302 微信授权 URL
  - `GET /wechat/oauth/callback?code=&state=` → code 换 openid → 回填 `notify_contact.wechat_openid` → 302 前端绑定结果页
- `WechatOAuthService`：code→openid（`https://api.weixin.qq.com/sns/oauth2/access_token?appid&secret&code&grant_type=authorization_code`）
- 接口鉴权：`authorize` 需登录态（校验联系人归属当前租户），`callback` 微信侧无鉴权，靠 state 防伪造
- **解绑**：联系人编辑页开放清空 openid（避免误绑）

## 8. 风险与边界

- **模板消息仅限服务号/认证订阅号**：当前公众号已认证 ✅；未认证号无模板消息权限
- **频控**：模板消息单用户 4 条/分钟（官方限制），告警风暴场景需在规则侧收敛（同设备离线只发一次，恢复再离线才重发——建议规则里配置）
- **未绑定用户**：发送时静默跳过并 warn（现有逻辑），建议在联系人页做绑定率提示
- **多租户**：本方案通道实例级配置天然支持多租户（各租户可建自己的 wechat 实例或共用全局）；如一个服务号全局共用，openid 全局唯一不冲突
